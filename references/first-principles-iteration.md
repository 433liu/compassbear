# First-Principles Iteration

Improve CompassBear by decomposing every requested feature into the underlying user pain.

## Rule

Do not copy competitor features because they look impressive. Ask what primitive they improve:

- claim discipline;
- evidence traceability;
- figure-as-argument reasoning;
- reviewer-risk detection;
- token-efficient triage;
- public installability;
- reproducible examples.

## Intake Table

| Candidate | User pain | CompassBear primitive | Adopt / adapt / reject | Smallest useful version |
|---|---|---|---|---|
| feature | pain | primitive | decision | implementation |

## Adoption Test

Adopt a feature only if it makes a research decision more defensible, more traceable or cheaper to reach. Reject features that merely create polished-looking output without improving evidence, scope or reviewer defense.

## Benchmark

Each upgrade should add at least one synthetic or anonymized example showing the expected behavior and a failure mode it prevents.
